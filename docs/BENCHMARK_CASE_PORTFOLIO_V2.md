# system-comparison-v2 案例组合与冻结分组

## 结论边界

当前案例池只能支持“多案例试点评测”，尚不能支持 HypoWeaver 或 Agent
Laboratory 具有普适科研能力优势的结论。Case 002 已被反复用于开发；Case 005
是已见过的验证案例；当前还没有满足一次性、盲输入和隐藏评测要求的准留出案例。

案例一旦进入下面的分组，不得根据系统结果重新分组或改变主评分资格。

## 已冻结案例

| 案例/输入视图 | 固定分组 | 当前用途 | 主评分资格 |
|---|---|---|---|
| Case 002 / `discovery_blind` | `dev` | 自主方法路由、政策面板执行与负结果校准 | 否 |
| Case 002 / `reproduction_aligned` | `dev` | 已知方法信息下的执行、敏感性和独立复算 | 否 |
| Case 005 / `discovery_blind` | `validation` | 省级面板关联任务的自主方法路由 | 否 |
| Case 005 / `reproduction_aligned` | `validation` | 双向固定效应、30 个聚类风险和复算能力 | 否 |
| Case 007 / `discovery_blind` | `validation` | 空间方法路由与缺口识别；当前只做预检 | 否 |
| Case 007 / `reproduction_aligned` | `validation` | SDM 执行合同与直接/间接/总关联分解；当前只做预检 | 否 |

Case 002 的两个 v2 开发视图冻结为同一份数据、字典和中立数据说明；仅方法信息
视图不同。固定敏感性合同为：政策前最后一期分组、稳定实体样本、企业层聚类、
替代结果、事件研究、伪政策时间，以及按 `idcode` 分配单元置换 199 次
（seed `12345`）。

Case 005 的两个验证视图冻结为同一份 30 省×11 年数据。该案例只允许条件关联
主张。`reproduction_aligned` 视图冻结省份和年份双向固定效应、按省份聚类，并
要求披露只有 30 个聚类的渐近推断风险。公开材料中的 `lnainex` 与数据列
`lntr` 冲突保持为未解决问题；面板门槛部分因门槛变量、搜索区间和重抽样规则
缺失而标记为 `unsupported_by_visible_contract`，不得猜测补齐。

Case 007 的两个验证视图冻结为同一份 30 省×13 年主表、30×30 行标准化空间
权重和精确省份映射。该案例提供了相对 Case 002/005 更高的方法多样性，但在
冻结空间面板稳健推断合同、独立 SDM 复算和替代权重矩阵语义之前，状态保持为
`capability_gap_not_scored`。当前运行只可检验系统能否识别缺口并拒绝或降级主张，
不能用于比较最终论文质量。

Case 005 与 Case 007 的本地 HypoWeaver 和 Agent Laboratory `validate-only` 均已
通过，隐藏参考访问均被拒绝。二者虽声明为 PLOS ONE S1 Data，源包中没有单独的
外发许可文件；向外部模型供应商发送可见内容前仍需为相应案例取得明确授权。

## 暂不运行：Case 006

Case 006 是高价值的下一阶段验证案例，但不能塞进当前共同政策时间点执行器：

- 政策采用存在至少两个批次，不能用一个共同 `post` 表示；
- 分配单元是省份，不是企业行；
- 少量企业跨省迁移，需要冻结迁移样本规则；
- 正确置换需要保持各采用批次规模，而不是逐行打乱处理变量；
- 省级聚类数较少，需要小聚类推断；两个主要结果还需要冻结多重检验校正。

在增加 cohort/adoption-time 字段、相对事件时间、迁移规则、按批次置换和小聚类
推断之前，Case 006 的状态固定为 `capability_gap_not_scored`。不能通过删除晚采用
省份或改成共同时间点来制造一个看似可运行的结果。

## 外发授权阻断：Case 001

Case 001 的可见说明明确写明 ESG 数据来自华证指数/Wind，公司财务、治理、行业
与交易数据来自 CSMAR 等商业数据库，并要求使用、共享和再分发遵守原授权协议。
在取得覆盖外部模型处理与数据外发的单独许可前，只允许本地只读预检，不得把
Case 001 的数据或派生可见内容发送给 DashScope 或其他外部供应商。

## 进入主比较前仍缺少的案例

正式主比较至少需要两个未参与开发和验证的 `quasi_holdout` 案例，并在运行前
冻结：仅使用 `discovery_blind` 视图、系统先后顺序交叉平衡、一次性 Run、双方
源码与配置哈希、隐藏参考哈希和评分 rubric。所有系统输出封存前不得打开隐藏
参考。若没有这些案例，Case 002 和 Case 005 的结果必须分别以 `dev` 和
`validation` 报告，不能合成“总体科研能力”主分数。
